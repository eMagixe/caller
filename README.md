# Caller

Приватные звонки **один на один** на Nuxt 4, Nuxt UI 4, Nitro и WebRTC. Интерфейс на русском, адаптирован для телефона и компьютера.

- Видео- и аудиозвонки, отключение микрофона и включение/выключение камеры во время разговора.
- Чат через WebRTC DataChannel, без передачи текста сообщений серверу приложения.
- Уникальная комната, одноразовое приглашение и подтверждение гостя организатором.
- Не более двух участников. Ссылка действует 30 минут, комната — до 12 часов.
- Восстановление WebSocket и повторный вход после перезагрузки страницы.
- Шифрование аудио/видео через DTLS-SRTP, чата через DTLS. Записи звонков нет.

## Локальный запуск

Нужны **Node.js 24 LTS** (либо совместимая версия из `package.json`) и npm.

```sh
nvm use
npm ci
npm run dev
```

Откройте **http://localhost:3000**. Создайте комнату, войдите и отправьте приглашение другому человеку. После его запроса нажмите «Впустить».

Для самостоятельной проверки откройте приглашение в **другом профиле браузера или приватном окне**. Две вкладки одного профиля используют общую сессию — вторая заменит первую. При проверке с реальными устройствами используйте наушники, чтобы избежать обратной связи.

Камера и микрофон доступны на `localhost` или по **HTTPS**. Обычный HTTP по IP-адресу компьютера не подходит для звонка с другого устройства. Для такой проверки настройте локальный HTTPS либо HTTPS-прокси и соответствующий `NUXT_APP_ORIGIN`.

## Docker Compose

Нужны Docker Engine или Docker Desktop с Compose v2. Node.js на хосте не требуется.

```sh
docker compose up -d --build
docker compose ps
docker compose logs -f caller
```

Без `.env` приложение открывается на **http://localhost:3000**. Если порт занят локальным `npm run dev`, остановите его либо задайте другой порт **вместе с origin**:

```sh
CALLER_PORT=3001 NUXT_APP_ORIGIN=http://localhost:3001 docker compose up -d --build
```

Compose читает существующий `.env` автоматически. Если в нём уже указан `NUXT_APP_ORIGIN`, будет использовано это значение, а не локальный адрес по умолчанию. Для публикации создайте `.env` на основе `.env.example` (если файла ещё нет), укажите настоящий HTTPS-домен, настройки TURN и, при использовании доверенного прокси, `NUXT_TRUST_PROXY=true`.

Порт контейнера опубликован только на `127.0.0.1` хоста. HTTPS и WebSocket Upgrade обслуживает внешний reverse proxy, например Nginx из `deploy/nginx.conf.example`. Если меняете `CALLER_PORT`, измените и порт в `proxy_pass`. Внутри контейнера `NITRO_HOST=0.0.0.0` задан намеренно — не заменяйте его на `127.0.0.1`, иначе проброс порта перестанет работать. Для прокси в отдельном контейнере потребуется общая Docker-сеть и upstream `caller:3000`.

TURN-сервер в Compose не включён: подключите существующий сервис через `NUXT_TURN_URLS` и `NUXT_TURN_SECRET` либо настройте coturn по разделу ниже. Дополнительные медиапорты у контейнера приложения открывать не нужно: он обслуживает страницу, HTTP API и WebSocket-сигнализацию, а WebRTC передаёт медиа между браузерами или через TURN.

Dockerfile собирает Nuxt в отдельном этапе на Node.js 24 и копирует в итоговый образ только `.output`. Приложение работает от пользователя `node`, файловая система контейнера доступна только для чтения, `/tmp` — временная. Healthcheck проверяет HTTP-ответ приложения; `restart: unless-stopped` перезапускает завершившийся процесс, но сам статус `unhealthy` не вызывает перезапуск. Секреты передаются при запуске, а `.env`, локальные зависимости и конфигурация `deploy` исключены из контекста сборки.

Проверка конфигурации и остановка:

```sh
docker compose config --quiet
docker compose down
```

После изменения кода повторите `docker compose up -d --build`. Запускайте **один экземпляр**: комнаты хранятся в памяти и сбрасываются при пересоздании или перезапуске контейнера. Постоянный том для текущей реализации не нужен.

## Проверки

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
```

`npm test` проверяет изоляцию комнат, одноразовость/срок ссылок, разрешения участников, отзыв сессий и закрытие комнаты. Браузерные тесты используют два изолированных контекста Chromium и синтетические камеру/микрофон: подтверждают передачу аудио/видео, состояние DTLS, чат в обе стороны, управление устройствами, повторный вход, HTTP/WebSocket-авторизацию и мобильную вёрстку.

Чтобы использовать уже установленный Chrome:

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chrome npm run test:e2e
```

Проверка production-сборки (остановите ранее запущенный сервер на порту 3000):

```sh
npm run build
E2E_PRODUCTION=1 npm run test:e2e
```

## Публикация

```sh
npm ci
npm run build
NUXT_APP_ORIGIN=https://call.example.com npm start
```

Используйте **один постоянно работающий Node-процесс** за HTTPS reverse proxy с поддержкой WebSocket Upgrade. `NUXT_APP_ORIGIN` — точный origin сайта без завершающего `/`; production API намеренно отклоняет операции, если он не настроен. Публичный origin должен быть единственным разрешённым доменом на прокси.

`npm run dev` читает `.env`; собранный Node-сервер сам этот файл не загружает. Передайте переменные через окружение сервиса, либо используйте `node --env-file=.env .output/server/index.mjs`.

Пример Nginx находится в `deploy/nginx.conf.example`. Настройте домен и TLS-сертификат. Прокси ограничивает размер HTTP-запросов и частоту запросов, передаёт Upgrade и сохраняет долгие соединения. Nitro использует экспериментальную интеграцию WebSocket, поэтому при обновлении зависимостей повторно прогоняйте браузерные тесты.

За этим прокси задайте `NUXT_TRUST_PROXY=true` и `NITRO_HOST=127.0.0.1`, чтобы приложение учитывало IP клиента для лимитов и не принимало прямые внешние запросы. Прокси должен **заменять** `X-Forwarded-For`, как в примере. Без доверенного прокси оставляйте `NUXT_TRUST_PROXY=false`: тогда используется адрес TCP-соединения. Лимит создания комнат — 10 в минуту на IP, изменяющих HTTP-запросов — 60 в минуту на IP.

### STUN / TURN

Без TURN звонки зависят от сетей участников. Для пользователей за NAT, в корпоративных сетях и мобильных сетях нужен собственный либо управляемый TURN-сервис. В `.env.example` перечислены настройки:

```dotenv
NUXT_APP_ORIGIN=https://call.example.com
NUXT_STUN_URLS=stun:stun.cloudflare.com:3478
NUXT_TURN_URLS=turn:turn.example.com:3478,turns:turn.example.com:5349
NUXT_TURN_SECRET=replace-with-a-long-random-secret
```

Пример coturn — `deploy/turnserver.conf.example`. Значение `static-auth-secret` должно совпадать с `NUXT_TURN_SECRET`; храните его в секретах окружения. Откройте порты 3478 TCP/UDP, 5349 TCP и диапазон UDP relay-портов из конфигурации, настройте сертификат и внешний IP при NAT.

Бэкенд выдаёт только авторизованным и одобренным участникам временные HMAC-учётные данные TURN сроком 12 часов (максимальная продолжительность комнаты). Сам общий секрет не попадает в клиентскую конфигурацию. TURN передаёт зашифрованные пакеты, а не расшифрованное видео. По умолчанию STUN обслуживает Cloudflare; при необходимости задайте свой сервер или пустой `NUXT_STUN_URLS`.

## Устройство и границы защиты

`app/composables/useCall.ts` управляет WebRTC, устройствами, соединением и DataChannel. `server/api/rooms/[id]/socket.ts` обменивает SDP/ICE и события управления через WebSocket. `server/utils/room-store.ts` хранит комнаты и обеспечивает разрешения. HTTP API создаёт комнаты, обменивает приглашение на сессию, обновляет ссылки и выдаёт ICE-конфигурацию.

Приглашение содержит случайный секрет 256 бит. Он находится во фрагменте URL (`#invite=…`), не передаётся при загрузке страницы и удаляется из адресной строки; до обмена хранится в sessionStorage. При подтверждении входа клиент отправляет его в JSON POST по HTTPS. Сервер хранит хеши приглашений и сессионных секретов. Сессия — отдельная для каждой комнаты cookie с `HttpOnly`, `SameSite=Strict`, ограниченным путём и `Secure` при HTTPS. Старый токен сразу перестаёт действовать при обновлении приглашения.

Токен даёт **право запросить вход**, а не подтверждает личность владельца. Организатор проверяет гостя и разрешает вход; до этого SDP/ICE не пересылаются, удалённая сторона не получает медиа или чат. Если неизвестный человек использовал пересланную ссылку, отклоните его и создайте новую. Для строгой привязки к конкретному аккаунту понадобятся аутентификация пользователей и список приглашённых аккаунтов.

WebRTC шифрует медиапотоки и канал данных между браузерами. HTTPS/WSS защищает сигнализацию. **Сервер сигнализации и код приложения должны быть доверенными**: отдельной проверки криптографических отпечатков или защиты от злонамеренного сервера здесь нет. Собеседник может записать разговор своими средствами. При прямом соединении участники могут узнать сетевые адреса друг друга.

Комнаты, сессии и ограничения частоты хранятся **в памяти одного процесса**. После перезапуска комнаты перестают существовать. Завершение звонка организатором удаляет комнату и отзывает доступ; выход гостя удаляет его сессию. Обновление страницы/обрыв сети оставляют сессию действующей до закрытия или истечения срока комнаты. Новое приглашение после ухода/отклонения гостя создаётся организатором. История чата существует только в памяти страницы (последние 200 сообщений) и очищается при выходе.

Для нескольких серверов нужны общее хранилище с атомарным погашением приглашений, распределённые лимиты и шина сигнализации. Текущую версию нельзя запускать с несколькими worker-процессами, в autoscaling или в среде короткоживущих serverless-функций.

Проверено автоматически в Chromium с тестовыми устройствами на одной машине. Реальные камеры, Safari/Firefox, мобильные устройства и соединение через отдельный TURN-сервер требуют проверки в вашей среде перед публичным запуском.
